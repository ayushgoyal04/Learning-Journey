# Next.js Project Structure & Key Concepts

This document explains the main files and concepts in a modern Next.js project using TypeScript and Tailwind CSS.

## Project Files Overview

- **tsconfig.json**: TypeScript configuration file. Not specific to Next.js, but enforces type checks and compiler options for your project.
- **postcss.config.mjs**: Configuration for PostCSS, often used with Tailwind CSS for advanced styling features.
- **package.json**: Manages project dependencies and scripts. Key scripts include:
  - `dev`: Starts the development server.
  - `build`: Builds the project for production, optimizing assets and code.
  - `start`: Runs the application in production mode.
  - `lint`: Checks code for issues using ESLint.
  - **dependencies**: Lists libraries used in your project.
- **next.config.ts**: Next.js configuration file. Allows customization of Next.js features, such as enabling/disabling features, setting up custom domains, and configuring image sources (e.g., allowing images from Wikipedia).
- **next-env.d.ts**: TypeScript declaration file, auto-generated by Next.js. Do not edit manually.
- **eslint.config.mjs**: ESLint configuration for code linting. Usually auto-generated; manual edits are rare.
- **node_modules/**: Directory containing installed dependencies. Often the largest folder in the project.
- **public/**: Static files (images, icons, etc.) served directly to the client. Accessible via URLs.
- **.next/**: Contains build and cache files generated by Next.js. Do not edit manually.
- **app/**: Main application code lives here. Contains routes, layouts, and global styles.
  - `favicon.ico`: Icon for the browser tab.
  - `globals.css`: Main CSS file for global styles.
  - `layout.tsx`: Defines the root HTML structure and layout for your app. Components rendered inside `{children}` are routed pages. You can also define fonts and metadata here.
  - `page.tsx`: The main route (homepage). Next.js uses file-based routing—create a folder and add a `page.tsx` to define a new route (e.g., `about/page.tsx`).

## Routing & Layouts

- **File-based Routing**: To create a new route, add a folder (e.g., `about/`) and a `page.tsx` file inside it. The exported component will be rendered for that route.
- **Layout Component**: The `layout.tsx` file wraps all routed pages. Anything outside `{children}` will appear on every page (e.g., navigation bars, footers).
- **Example:**
  ```tsx
  export default function About() {
    return <div>My new page</div>;
  }
  ```
- **Metadata & Fonts**: Layouts can define metadata (for SEO) and custom fonts for the app or individual pages.

## Components in Next.js

- **Functional Components**: The standard for React and Next.js. Class components are rarely used.

## Server & Client Components in Next.js

Next.js supports two types of components:

- **Server Components**: Rendered on the server. Their HTML is sent to the client, but their code never runs in the browser. By default, all components are server components unless you specify otherwise.
  - Cannot use client-side features like React hooks (`useState`, `useEffect`) or browser events (`onClick`).
  - Great for fast initial page loads and SEO, since no client-side JavaScript is needed for these components.
  - Can be asynchronous:
    ```tsx
    export default async function MyComponent() {
      // Fetch data here
      return <div>Server-rendered content</div>;
    }
    ```
  - Useful for fetching data from APIs before rendering, without relying on client-side effects.

- **Client Components**: Run in the browser. To declare a client component, add the directive at the top:
  ```tsx
  "use client";
  ```
  - Can use React hooks and browser events.
  - Use for interactive UI elements.

**Tip:** If you log to the console in a server component, the message will appear in the server logs, not the browser console.

**Composition:** You can nest client components inside server components, but not the other way around.
